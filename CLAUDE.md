# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Model that suggests the CPV code (EU public procurement vocabulary, ~9 500 codes in a tree: division 2 digits → group 3 → class 4 → category 5 → full 8) from a Portuguese public contract description, trained on Portal BASE contracts (dados.gov.pt). The goal is a ranked top-5 of specific codes; division-level accuracy is only for comparison with published benchmarks. Plan: TF-IDF + logistic regression baseline, then fine-tune **BERTimbau base** and **Albertina PT-PT 100M** as classifiers on a rented GPU. AMALIA and Qwen were explicitly dropped. Epic E5 (BERTimbau and Albertina) is in `docs/backlog.md` and in progress (E5-T1 to E5-T4 done; next is E5-T5, Albertina. E5-T4, the first BERTimbau training, gave top-5 code 73.39% against TF-IDF's 78.35%, section 22 of `docs/qualidade_dados.md`; a single run, the decision is E5-T6's. Its memorise signal failed as pre-registered, 86/100 in 30 epochs, section 21; a 100-epoch diagnostic reached 100/100 and E5-T5 uses 100 epochs, a change made after seeing that result. Pending decision 1, the epic's GPU spending cap, is closed at $20: about $1.86 spent, and a full 3-epoch training costs about $0.83 on an RTX 4090, so the E5-S1 grid will have to shrink); no GPU training starts before the training window is settled: spike E4-S2 (`notebooks/09_janela.ipynb`, section 18) found the window from 2019 beats 2022 with sklearn's default stopping rule, but spike E4-S6 (`notebooks/10_janela_24_epocas.ipynb`, section 19) found it ties with the 24 fixed epochs (the default rule stopped the 2022 training too early), so `TRAIN_START` stays 2022-01-01 (decision 1).

All docs, notebooks, comments and replies are in **European Portuguese** (exception: `videos/notebooks/`, see Conventions). The user is learning ML through this project: go step by step, define every term with a concrete example, give one recommendation at a time, say which lessons generalize beyond CPV, and never present unverified facts as certain. Do not write day-by-day plans ("Dia 1, Dia 2").

## Architecture and data flow

`data/raw/*.xlsx` → `convert_to_parquet.py` (streams rows with openpyxl, writes **every column as text**, no transformation) → `data/processed/raw/contratosAAAA.parquet` → `prepare.py` → three output files. `data/` and `.venv/` are not in git.

- `src/cpv_data.py` holds the rules shared by the pipeline and the notebooks: CPV code extraction, code level (trailing-zeros heuristic), text normalization, and the split constants `TRAIN_START` (2022-01-01), `VAL_START` (2025-10-01), `TEST_START` (2025-11-01), `YEAR_END` (2026-01-01). Change split dates only here; `prepare.py --inicio-treino AAAA-MM-DD --saida PASTA` (E4-T4) prepares another train window without changing `TRAIN_START` (it refuses a non-default start without `--saida` or with `--saida data/processed`, so that folder is never overwritten with another window). `run` also raises `DataCheckError` if a contract with a copy in validation/test ends up in another period because an older copy won the dedupe (decision 3), so evaluation is identical across windows or preparation stops.
- **The file year (and the `Ano` column) is the contract's signing year, not its publication year.** Contracts published in a given year are spread across several files, so always read all files and filter by `dataPublicacao` (`load_contracts` does this per file to save memory).
- `src/prepare.py` is a sequence of small testable functions (`load_one` → `dedupe_ids` → `add_columns` → `build_train` / `build_eval` → `check_sets` → save), orchestrated by `run(raw_dir, out_dir)`. Each step maps to a numbered decision in `docs/qualidade_dados.md`. Key rules:
  - input text = `objectoContrato` + `descContrato` (only if different) + `DescrAcordoQuadro` (if present), joined with `" | "`;
  - label = first CPV code; all codes kept in `codigos` (space-separated) for evaluation;
  - **train only**: drop division-level codes (`XX000000`), then one example per normalized text with its most common code (tie → smallest code); `n_contratos` keeps the original count;
  - validation/test keep every contract and get `visto_no_treino` (text also present in train), to measure memorization separately;
  - text identity uses a 64-bit hash of the normalized text (memory).
  - `check_sets` raises `DataCheckError` (not `assert`, which `-O` would disable) on leakage between sets, dates outside a period, division-level codes in train, repeated train texts, malformed codes, or "None"/"nan" written into text.
- `src/bert_models.py` is the single source for the two E5 models: Hugging Face name and pinned `revisao` (a commit sha) of `neuralmind/bert-base-portuguese-cased` and `PORTULAN/albertina-100m-portuguese-ptpt-encoder`, plus `COMPRIMENTO_MAXIMO` = 256 tokens for both, chosen by the E5-T1 rule (smallest of 128/256/512 holding >= 99% of train texts with special tokens; `notebooks/11_comprimento_tokens.ipynb`, `make tokens`, section 20). BERT training (E5-T2) must read it. BERTimbau's tokenizer has no `model_max_length`, so `truncation=True` alone does not cut at 512: always pass `max_length`. Albertina uses the English DeBERTa tokenizer (~2.7 tokens per word vs ~2.05). `transformers==5.17.0` / `tokenizers==0.23.2` are pinned; tokenizers work without `torch`.
- `src/bert.py` / `src/train_bert.py` (E5-T2) fine-tune either E5 model as a classifier: `train_bert.py --modelo bertimbau|albertina|<local folder> --treino --validacao --saida --dispositivo cuda|cpu` (default `cuda`) plus hyperparameter flags; it reads `bert_models.py`, passes inputs through `check_inputs` (refuses the test set), writes small files to `--saida` (suggestions τ = 0 and τ = 0.25 per epoch and for the last epoch, same format as TF-IDF, plus `treino.json`) and big ones under `models/bert/` (per-epoch validation scores ~0.3 GB/epoch, one checkpoint per epoch), which stay on the pod (layout: `--saida/epoca_<k>/` + last epoch at the root; `models/bert/<saida name>/pontuacoes/epoca_<k>.npy` float32 n_val × n_labels in `validacao.parquet` row order, `etiquetas.json`, `log_prior.npy`; `.../checkpoints/checkpoint-<step>/` with `id2label`). Default `--saida` is `metrics/bert/<modelo>`; it refuses non-empty checkpoint/score folders and a `--saida` with old `epoca_*`, so re-running needs them removed. HF `Trainer` with `save_strategy="epoch"`, `save_only_model=False` (each checkpoint keeps optimizer, scheduler and RNG state, ~3× the model; user decision): `--retomar` (`run(retomar=True)`) resumes an interrupted run from the last checkpoint with `resume_from_checkpoint`, skips a checkpoint saved only halfway (no `trainer_state.json`, which the Trainer writes last), runs only the missing epochs and rebuilds `por_epoca` from each `epoca_<k>/epoca.json`; it refuses to resume with arguments other than those saved in `--saida/argumentos.json` (full train/validation/model paths, checkpoint and score folders, resolved `max_length`, lote, épocas, semente, τ, ...); `treino.json` records `n_gpus` (with several GPUs the Trainer uses all of them and the effective batch is lote × n_gpus); tested to give the same scores as an uninterrupted run, fp32 (models are loaded with `dtype=torch.float32` because transformers 5 keeps the file dtype and Albertina is stored in bf16). Hyperparameter defaults (`TAXA_APRENDIZAGEM` 2e-5, `LOTE` 32, `EPOCAS` 3, `AQUECIMENTO` 0.1, `DECAIMENTO_PESOS` 0.01, `SEMENTE` 0) are the Devlin et al. 2019 recipe; E5-T4 sets the real ones in a YAML. Albertina is **DeBERTa v1** (`model_type: "deberta"`), not v2. `bert.check_gpu()` (`make verificar-gpu`) raises if `torch` sees no GPU. `torch==2.14.1` and `accelerate==1.15.0` are pinned in `requirements-cpu.txt` (CPU wheel from the PyTorch index: `+cpu` on Linux/CI, plain wheel on the Mac via a `sys_platform` marker) and `requirements-gpu.txt` (PyPI wheel, bundles CUDA 13.0, needs NVIDIA driver >= 580: pod); `requirements.txt` has no torch (but pins `huggingface_hub` and `safetensors`, which load the models). Tests (`make test-bert`) use tiny random-weight models on CPU; `tests/unit/test_requisitos.py` guards the pins (same torch/accelerate in both files, no torch in `requirements.txt`, CI installs the CPU file) and `tests/integration/test_makefile_bert.py` the `treinar-bert`/`verificar-gpu` targets (`make -n`). `docs/maquina_runpod.md` section 7 is the GPU pod guide: on the GPU pod the project lives in `/workspace/projeto_CPV` (the volume), because the container disk is wiped when a pod stops or restarts and the checkpoints must survive for `--retomar`. `bert.predict_scores` puts the model in `eval()` (no dropout) and restores train mode; a unit test with dropout 0.5 guards it (the tiny test models have no dropout).
- `src/registo_bert.py` (E5-T3, `make registar-bert PASTA=...`) logs one BERT training as one MLflow run (experiment `treinos_bert`, laptop `mlflow.db`) from its copied `--saida` folder: params (hyperparameters, model and revision, train dates, `treino_sha256`/`validacao_sha256`, `git_commit`, `git_alteracoes_por_gravar`, YAML path and sha; `None` logged as `"nenhum"`), tag `experiencia_yaml` with the YAML text, per-epoch top-1/top-5 code and class (all and new text) with `step` = epoch (the default τ uses the gate's names, other τ get `_tau<τ>`), `perda_treino`, and cost metrics. The pod's `mlflow.db` is never copied (it would overwrite the laptop's gate/history runs). It refuses a laptop `validacao.parquet` (or the `treino.parquet` next to it) whose SHA-256 differs from the pod's (`treino.json` `sha256`), plus the gate's test/date/window checks, and skips a folder already logged (tag `treino_json_sha256`, FINISHED runs only). For this, `train_bert.py` writes `sha256`, `git` (`read_git`: `git rev-parse HEAD` and `git status --porcelain --untracked-files=no` at the start of training, so the untracked `--saida` folder that appears mid-training does not break `--retomar`; without git, Nones plus a stderr warning on CPU; with `--dispositivo cuda` training refuses to start without a commit or without `--experiencia`, so a paid run is never unidentifiable) and `experiencia` (`--experiencia <yaml>`: path, sha, text; recorded only, it does not set hyperparameters; its sha is in `argumentos.json`, so resuming with another YAML is refused; `argumentos.json` also holds `treino_sha256`, `validacao_sha256`, `git_commit` and `git_alteracoes_por_gravar`, so resuming after a code rsync or with re-prepared data is refused) into `treino.json`. `file_sha256` and `MAX_YAML` live in `cpv_data.py`, so `registo_bert.py` does not load torch. A session autouse fixture in `tests/conftest.py` replaces `train_bert.git_info`, so no test runs the real git.
- `src/labels.py` (`collapse_rare_codes`) builds the training label at training time, not in `prepare.py`: a code with fewer than N training examples backs off to its class (4 digits), then its group (3 digits), else the example is dropped; never to the division. N is a hyperparameter (5, 10 or 20, default 10) to be chosen with TF-IDF on validation; counts come from train only. Evaluation keeps the original label.
- `src/evaluation.py` scores ranked suggestions (pandas Series of 5-code lists) against `codigos`; it reads and writes no files. Measures: `codigo` (exact match; only contracts with a code below division level count, since the model never suggests divisions), `classe` (4 digits, codes of level >= 4), `divisao` (2 digits), plus a `so_divisao` row for contracts whose codes are all division-level. `report` splits all vs. new text (`visto_no_treino == False`); `hierarchical*` give partial credit (Kiritchenko hP/hR/hF) for display only.
- `src/baselines.py` is the "most common codes" baseline (E4-T2): always suggest the 5 most frequent training labels, counted once per training row after `collapse_rare_codes` with the model's N (tie → smallest code). Weighting rows by `n_contratos` is optional and only for comparison: it gave an easier baseline on validation (decision 10). Its validation numbers (`notebooks/03_regua.ipynb`, `make regua`) are section 12 of `docs/qualidade_dados.md`; the same 5 labels come out for N = 5, 10 and 20.
- `src/comparison.py` decides between two options with a paired bootstrap (1 000 samples, same sample for both, a difference counts if one side wins in >= 95%). `choose` applies the E4 rule: top-5 on `codigo` decides, top-5 on `classe` is the guard, ties fall back to a default. `compare` runs it for every measure × metric (~40 s on 24k contracts).
- Training runs on a rented **Runpod** pod, not the laptop (decision 3 of E4; Hetzner was dropped). Spike E4-S0 measured a full TF-IDF training (`scripts/ensaio_treino.py`, results in `metrics/e4_s0/`): 7.7 min / 5.7 GB with N = 10, 10.3 min / 7.2 GB with N = 5, on a `cpu3g` CPU pod with 8 vCPU and 32 GB at $0.32/h. `docs/maquina_runpod.md` is the step-by-step guide (copy only `treino`/`validacao` parquet, never `teste`; read memory from the cgroup, not `free`). The Runpod MCP plugin (`runpod@runpod`) is connected and the SSH key is `~/.ssh/runpod_cpv`. A pod bills while it exists, busy or idle: state the hourly price before creating one, and terminate it (then confirm with `list-pods`) as soon as results are copied back.
- The TF-IDF model is `src/tfidf.py` (`train`, `suggest`): TF-IDF (words + word pairs, `min_df=2`, float32) + `SGDClassifier(loss="log_loss")` (one-vs-rest logistic regression), decision 5 of E4, confirmed in E4-H1. Spike E4-S4 (decision 6, section 14 of `docs/qualidade_dados.md`, `notebooks/05_tfidf_afinacao.ipynb`) set `ALPHA = 1e-7` (sklearn's default 1e-4 starved rare labels: top-5 code 43% → 77%) and `TAU = 0.25`: suggestions rank by score − τ·log(train label frequency) (Menon et al. 2021 logit adjustment); `train` stores `log_prior_` on the model. `suggest` defaults to `TAU` (pass `tau=0.0` for score order only). Spike E4-S5 (decision 7, section 15, `notebooks/06_tfidf_epocas.ipynb`) found α = 1e-8 clearly worse (so α = 1e-7 is no longer an untested edge) and set `EPOCAS = 24`: `train(..., epocas=EPOCAS)` trains every label exactly 24 epochs (`max_iter=24, tol=None`) instead of sklearn's early stopping (`tol=1e-3` on the loss summed over all ~478k examples, `n_iter_no_change=5`, `learning_rate="optimal"`, whose step size also depends on α). `epocas=None` / `train_tfidf.py --regra-por-defeito` brings back sklearn's rule; spike E4-S2 must use it. Spike E4-S1 (decision 9, section 16, `notebooks/07_tfidf_grelha.ipynb`) instead tested the grid N × epochs × τ as a cross-product (α fixed at 1e-7, 18 trainings, τ only re-ranks at suggest time) and confirmed the E4-S5 config (N = 10, 24 epochs, τ = 0.25) as the best of the 54 combinations, reproducing E4-S5 exactly. Spike E4-S3 (decision 7 of `docs/qualidade_dados.md`, section 17, `notebooks/08_entidade.ipynb`, `experiencias/e4_s3.yaml` in `modo: entidade`) tested `train_tfidf.py --com-entidade` (`with_entity`: `adjudicante | texto` in train and validation): +2.4 points top-5 code, but more generic first suggestions (level <= 3), so by the pre-registered rule the entity stays **out**; the default text is unchanged. Spikes E4-S2 and E4-S6 (`experiencias/e4_s2.yaml`, `e4_s6.yaml`, `modo: janela`) prepared and trained other windows on the pod (the 2019 preparation peaks at 4.3 GB and does not fit the laptop; `data/janelas/2019/` came back, `data/janelas/2025/` was re-prepared on the laptop) and decided on the validation contracts whose text is new to the 2019 train. Passing `max_iter`/`tol` together with `epocas` raises. `LogisticRegression(solver="saga")` does not finish in useful time with ~3 000 labels. `src/train_tfidf.py` trains on the pod (`make treinar-tfidf`), refuses the test set by name (`teste.parquet`) and by dates (`check_inputs`/`check_dates`: train must end before `VAL_START`, validation before `TEST_START`; also used by `curva_epocas.py` and the gate), and writes to `metrics/tfidf/` by default `sugestoes_validacao.parquet` (τ = 0), `sugestoes_validacao_tau0.25.parquet` (the default model) and `treino.json`, whose `ficheiro_do_modelo_por_defeito` names the file to evaluate (peak ~10 GB RSS; cgroup peak 11.6 GB in E4-S4 and 16.4 GB in E4-H1, on a 32 GB pod; `metrics/*/pod_info.json`). `metrics/e4_h1/`, `metrics/e4_s4/`, `metrics/e4_s5/`, `metrics/e4_s1/`, `metrics/e4_s3/`, `metrics/e4_s2/` and `metrics/e4_s6/` are frozen records that tests and notebooks 04–10 read; never write into them. Notebooks evaluate on the laptop. The saved model (~4.8 GB, `models/`, not in git) does not fit in laptop RAM, so `src/suggest.py` runs on the pod. `scikit-learn==1.7.2` is pinned in `requirements.txt`.
- Spikes write their options and comparison order **before running** in `experiencias/<spike>.yaml` (pre-registration; a unit test hard-codes the backlog's list). `scripts/correr_experiencia.py <yaml> alpha|epocas` reads it and runs the phase's trainings in parallel on the pod (`--paralelo`, `--n-jobs` each; E4-S5 used a 32-vCPU `cpu3g` pod, 4 × 8, $1.28/h), passing `--regra-por-defeito` when the YAML's `epocas.em_vigor` is null; the deciding notebook reads the same YAML with `ler`. Write YAML numbers with a dot (`1.0e-7`): PyYAML reads `1e-7` as a string, and `ler` rejects it. `scripts/curva_epocas.py` gives an approximate per-epoch curve (`partial_fit`: same example order every epoch, unlike `fit`). Without `--treino`/`--validacao`, `train_tfidf.py`, `curva_epocas.py` and `correr_experiencia.py` train on the real data, which does not fit the laptop: in tests and mutations always pass tiny parquet paths.
- The quality gate (E4-T5, decision 8 of E4) is `src/model_gate.py` (`make portao PASTA=metrics/<run>`): champion/challenger. `metrics/validacao.json` (committed) holds the champion's validation top-5 (code and class, all contracts and new text, read from the `ficheiro_do_modelo_por_defeito` of the run's `treino.json`); a new run is refused if **any** of the 4 drops (MLflow `validate_evaluation_results` with the champion's value as `MetricThreshold(threshold=...)`, since `min_absolute_change` must be > 0 and would reject ties), and then the file is left untouched (it also raises `GateError` if the champion was scored on another validation: different `contratos`, `periodo` or `contratos_sha256`, a SHA-256 of the validation `idcontrato` list; or if the run's `treino.json` says the train ends on/after `VAL_START` or read `teste.parquet`, or starts on another day than the `treino.parquet` next to the validation file: another window must be gated with `--validacao data/janelas/<year>/validacao.parquet`, since `visto_no_treino` depends on the window). A tie (all 4 equal) is accepted but keeps the champion, so the file keeps pointing at its frozen folder and never at `metrics/tfidf/` (rewritten by the next training); only a rise with no drop replaces it. `run` returns `(block, "aceite" | "empate")`. The first champion is `metrics/e4_s1/n_min_10_ep_24/`. Every gate run is logged to MLflow in a local SQLite file `mlflow.db` at the repo root (not in git; `make mlflow` opens the UI on port 5000); only params and metrics, never data or models. CI has no data: `tests/unit/test_model_gate.py` checks the committed file comes from validation and compares it with `main`'s copy, which the workflow writes to `$VALIDACAO_MAIN` (the test skips locally). Tests must pass a temporary `tracking_uri`/`--tracking`, never the real `mlflow.db`. `mlflow==3.17.1` is pinned. `scripts/registar_historico.py` (`make historico`) logs every frozen run under `metrics/` (one MLflow run per suggestions file / τ, plus the régua and the E4-S5 per-epoch curve with `step` = epoch) into the `historico_e4` experiment, outside the gate; runs from another train window are scored with `data/janelas/<year>/validacao.parquet` (detected by comparing `treino.json`'s start date with `data/processed/treino.parquet`), and existing run names are skipped. The user wants every training and evaluation visible in MLflow from now on.

Every "does not fit the laptop" statement in this file was measured on the old machine. Whether those jobs (e.g. the 2019 window preparation, 4.3 GB peak, or loading the ~4.8 GB TF-IDF model) now fit has not been measured. ## Conventions

- To understand the code (where a rule lives, who calls a function, what an edit affects), start with the `codegraph_explore` tool (index in `.codegraph/` at the project root): one call returns the verbatim source of the relevant symbols, the call paths between them and the blast radius. For decisions, numbers and project status keep reading the `.md` files in `docs/` — the graph only covers code.
- `src/` holds only pipeline code (code that transforms data, trains or evaluates). Exploration, counts and one-off analysis go in `notebooks/`; rules that must always hold become checks in the pipeline and tests.
- Every number written in `docs/*.md` must come from a notebook cell or pipeline output, not from ad-hoc terminal commands. Sections 1–6 of `docs/qualidade_dados.md` were measured on the 2025/2026 files only; sections 7–10 (`notebooks/01_exploracao.ipynb`) use the final train (Jan 2022–Sep 2025, all files), and section 10 reads `data/processed/treino.parquet`, so `prepare.py` must run before that notebook. Its train-contract count and "outside the most common code" count must match the `prepare.py` funnel (section 11).
- Never look at the test set (contracts published Nov–Dec 2025) during exploration or decisions; use the validation set (Oct 2025) to compare options. 2026 data is held in reserve.
- `docs/workflow.md` (CRISP-DM phases with checkboxes) is the plan and status; `docs/backlog.md` holds the epics, user stories, technical tasks and spikes with acceptance criteria (done epics and the next one, written with the `writing-epics-and-stories` skill); `docs/qualidade_dados.md` holds measurements and numbered decisions (the E4 epic's own decisions are numbered separately at the end of the E4 section of `docs/backlog.md`); `docs/maquina_runpod.md` is the rented-machine guide; `docs/como_funciona_tfidf.md` walks through the TF-IDF model with a toy example; each folder has a `readme.md` describing its files; `metrics/` holds committed result files that numbers in the docs cite; `docs/dados.md` describes the 39 columns and whether each exists when the CPV is chosen (columns known only after award are leakage); `docs/prs/pr_<ID>.md` holds each PR description (committed, written with the `writing-pull-requests` skill).
- When changing a rule in `prepare.py`, update the hand-made contracts in `tests/integration/test_pipeline.py`, which builds `.xlsx` files and runs the full pipeline end to end. New tests should be checked by injecting the bug they target (mutation testing).
- `videos/` holds the video plans and `videos/notebooks/` the notebooks shown on screen. Those notebooks are in English, take no decisions and run from any folder inside the repo (they look for `src/` upwards).
- `notebooks/00_qualidade.ipynb` has saved outputs from the 2025 and 2026 files only, while `load_contracts` now reads every file by default: re-running it changes the numbers behind sections 1–6 of `docs/qualidade_dados.md`.
- The user often has notebooks open in Cursor, which can save a stale version over a regenerated one. Check the file on disk (cell count, mtime) before and after rewriting a notebook, and don't commit a notebook that changed unexpectedly.
